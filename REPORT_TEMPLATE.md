# EMO Client Report — Fixed Approved Template v1

> This template is FIXED. Every client report MUST contain all 8 sections in this
> order with these headings. No section may be omitted; mark N/A explicitly with reason.
> Generated by `shared/report.py` — manual edits after generation void the QA stamp.

## 1. Identification
| Field | Value |

| Hardware (GPU / VRAM split observed) | |

## 2. Executive verdict
One paragraph: total score, tier, single decisive strength, single decisive weakness, deploy recommendation.

## 3. Score tables
Per-suite tables (test / result / secs). Automated totals per batch + grand total.
Qualitative overrides listed explicitly (e.g. T5) — never silently merged.

## 4. Efficiency (agent-loop only, if run)
calls / failed / recoveries / tokens / latency / forbidden / diff-clean / stopped-cleanly (A14).

## 5. Failure record
Every FAIL with: raw sample (trimmed), LOG excerpt, verdict class
[harness-artifact | genuine | budget-limited | unstable-needs-retest], evidence link (results JSON key).

## 6. Methodology notes
Budgets used (T/R/H), think policy, human corrections applied, any re-runs and why,
known unstable tests (H3 triple-run rule), tunnel interruptions if any.

## 7. QA stamp
Result of `qa_check()`: PASS or FLAGGED + checklist table below. A FLAGGED report
must not be presented as final.

| Check | Rule | Status |
|---|---|---|
| completeness | all 25 tests present, no errors = infra-failures | |
| trials | trials ≥ 1 recorded; n=3 for final claims | |
| raw evidence | every FAIL has non-empty sample+log | |
| budget compliance | T≤512/R≤600/H≤2048 (or documented override) | |
| human-review gates | H3 + T5 reviewed by human | |
| comparability | same PROMPT_PACK + temp + harness as baseline | |
| endpoint stability | no 404/timeout streak mid-run | |

## 8. Limitations & signature
Single-run caveat (<3pp = noise), hardware specificity, date. Generated-by line (tool + timestamp).
